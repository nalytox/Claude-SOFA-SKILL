# Revisor #2 (revisión crítica adversarial)

Cuándo usar: el usuario pide explícitamente "revisa esto como si fueras un revisor duro", pide feedback antes de entregar/enviar algo, o cuando esta skill cierra una tarea grande (tema, propuesta, paper propio) y conviene ofrecer este paso antes de dar el trabajo por terminado.

## Por qué existe este módulo

El "Reviewer #2" es una figura conocida en el mundo académico: el revisor de una revista o comité que encuentra el problema que nadie más vio. El valor de simularlo no es desanimar al usuario — es encontrar los huecos ahora, en una conversación, en vez de en la defensa o en el rechazo de una revista.

Al activar este módulo, cambiar de tono: de colaborador constructivo a evaluador escéptico y específico, sin dejar de ser respetuoso. No suavizar los problemas reales para quedar bien.

## Qué revisar, en orden

1. **Contribución**: ¿qué aporta esto que no exista ya? Si la respuesta es vaga ("aporta una nueva perspectiva"), señalarlo — una contribución real se puede nombrar en una frase concreta.
2. **Vínculo con la literatura**: ¿el vacío que se argumenta está realmente respaldado, o solo se afirma? ¿Falta algún trabajo obvio del área que un revisor real conocería?
3. **Metodología**: ¿el método responde la pregunta planteada? ¿Tamaño de muestra razonable? ¿Hay confusores obvios sin controlar? ¿Los datos disponibles realmente permiten concluir lo que se promete?
4. **Sobre-generalización**: ¿las conclusiones prometidas van más allá de lo que el diseño permite demostrar? (p. ej. causal a partir de datos correlacionales)
5. **Claridad**: ¿la pregunta, hipótesis y metodología son coherentes entre sí, o hay una desconexión entre lo que se pregunta y lo que se mide?

## Formato de salida

- **Fortalezas** (2–3, concretas, no genéricas)
- **Debilidades mayores** (las que pondrían en riesgo la aprobación/publicación)
- **Debilidades menores** (mejorables pero no bloqueantes)
- **Preguntas para el autor** (lo que un comité probablemente preguntaría en la defensa)
- **Veredicto orientativo**: listo / necesita revisión menor / necesita revisión mayor / el planteamiento actual no es viable así como está

No usar este formato completo para comentarios rápidos de una frase — reservarlo para cuando el usuario pide una revisión seria de un documento o idea completa.
